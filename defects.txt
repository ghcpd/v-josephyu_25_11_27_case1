Defects & Documentation Mismatches

Summary:
- The README contains several incorrect or misleading entries. Below are items found, reproduction steps, and traces.

1) Virtualenv activation
- README: "python3 -m venv .venv" and "source .venv/bin/activate"
- Problem: Windows environment uses different commands. Also `python3` may not exist on Windows.
- Reproduction: On Windows PowerShell:
  - Running `python3 -m venv .venv` results in "python3: The term 'python3' is not recognized..." error unless `python3` alias exists.
  - Running `source` in PowerShell errors: 'source' is not recognized.
- Fix: Use `python -m venv .venv` and use PowerShell activation: `.\.venv\Scripts\Activate`.

2) Running the app with --host and --port flags
- README: `python app.py --host=0.0.0.0 --port=8080`
- Problem: `app.py` runs `app.run(debug=True)` and ignores CLI flags; Python's default `sys.argv` isn't parsed so passing `--host` causes a harmless behavior or sometimes may be ignored (no error here). Using Flask CLI is recommended to support host/port flags.
- Reproduction: Running `python app.py --host=0.0.0.0 --port=8080` starts the app on 127.0.0.1:5000 (default) as the code does not parse flags.

3) Incorrect route names in README (signup/signin vs register/login)
- README: `/signup` and `/signin`
- Actual: The app uses `/register` and `/login`. 
- Reproduction: GET /signup returns 404; GET /register returns 200.

4) API endpoints mismatch
- README: `/api/register` and `/api/login`
- Actual: No API endpoints under `/api`. The UI uses blueprint `auth` at `/register`, `/login`.
- Reproduction: GET /api/register returns 404.

5) Password minimum length
- README: Min length 3
- Actual: In code validators are `Length(min=6, ...)` in `auth.py`.
- Reproduction: Attempt to register with password less than 6 characters fails the validator and displays error message on the form.

6) Email optional vs required
- README: Email is optional
- Actual: Email is part of `RegisterForm` with `DataRequired()` and DB schema requires `email` unique and NOT NULL. Registration without email fails.
- Reproduction: Submitting register form without email shows validation errors.

7) Database file path mismatch
- README: `data/database.sqlite3`
- Actual: `app.py` sets `app.config['DATABASE'] = 'app.db'` (at repository root).
- Reproduction: Database 'app.db' is created on first run. 'data/database.sqlite3' not used.

8) Server-side session store mismatch
- README: Sessions stored in Redis
- Actual: The app uses default cookie session (`flask-login`) and no Redis integration.
- Reproduction: There is no Redis-backed session; session keys are encrypted cookie-based.

9) Environment variable `FLASK_SECRET` mismatch
- README: Use `FLASK_SECRET` to configure CSRF
- Actual: `app.py` uses `app.config['SECRET_KEY']` hardcoded; `FLASK_SECRET` env var is not referenced.
- Reproduction: Setting FLASK_SECRET has no effect unless `app.py` is modified to read it.

10) Tests command in README
- README: `bash run_tests.sh` exists but was missing earlier; added by this work. Running tests now passes (see traces below).
